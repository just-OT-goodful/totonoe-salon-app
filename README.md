# 整えサロン 予約アプリ

会員登録不要の、整えサロン専用の予約アプリ（承認制）。
フレームワーク・ビルド不要。素のHTML/CSS/JavaScriptのみで構成しています。

仕様は [`../docs/要件書.md`](../docs/要件書.md) を参照してください。

## 動かし方

`index.html` をブラウザで開くだけです。Node.js等のインストールは不要です。

- ローカルで試す：`index.html` をダブルクリック、またはブラウザにドラッグ＆ドロップ
- 公開する：このリポジトリのGitHub Pagesで公開しています（下記）

予約データ・サロン設定（お知らせ・連絡先・メニュー・休業日など）は **Supabase（データベース）** に保存され、
お客様・管理者のどちらの端末からアクセスしても同じ内容が共有されます（下記「データベース（Supabase）」参照）。
プロフィール（氏名・電話・メール）と文字サイズの好みだけは、この端末だけのローカル設定として保存されます。

## データベース（Supabase）

- プロジェクト：`totonoe-salon-app`（組織 `tani`、Free、ref `idswizeiqkssqogmbwbz`、東京）
- ダッシュボード：https://supabase.com/dashboard/project/idswizeiqkssqogmbwbz
- `index.html` 内の `SUPABASE_URL` / `SUPABASE_ANON_KEY`（publishableキー）は公開して問題ありません。
  RLS（行レベルセキュリティ）を有効化し、テーブルへの直接アクセスは不可。すべて `supabase/schema.sql` で
  定義した SECURITY DEFINER の関数（RPC）経由でのみ読み書きする構成です。
- スキーマ定義：[`supabase/schema.sql`](./supabase/schema.sql)（冪等。SQL Editorで再実行してもOK）
  - `bookings`：予約データ
  - `app_settings`：お知らせ・連絡先・休業日・予約不可時間・メニュー・管理者パスコード（ハッシュ化）
- 管理者操作（承認／却下／設定変更）は、クライアントから送られたパスコードをDB側（`pin_hash`列、pgcrypto）で
  照合してから実行する。お客様の端末からはパスコードを知らない限り何も変更できない。

## PWA（ホーム画面に追加）

`manifest.webmanifest` と `sw.js`（最小限のService Worker）により、スマートフォンのブラウザで
上記URLを開き「ホーム画面に追加」すると、アプリのように使えます。

## 実装済みの機能

- ホーム：お知らせ表示、次回予約のリマインド（承認待ち／確定）、前回メニューでの再予約導線
- 予約フロー：メニュー選択 → 日付カード＋時間リスト → お客様情報（再来店時は自動入力・スキップ）→ 確認 → リクエスト送信（承認待ち）
- アクセシビリティ：文字サイズ「標準／大」切替、大きめのタップ領域、選択のチェックマーク表示
- マイページ：来店履歴（電話番号で紐付け）、前日24:00までの自己キャンセル
- お問合せ：電話・メール・Instagram・ホームページ
- 管理者画面（`#admin`）：統計、お知らせ編集、休業日（不定休）・予約不可時間の複数選択編集、
  承認／却下、確定予約の取り消し、メニュー編集、連絡先編集、承認／却下時の通知メール文面プレビュー、
  パスコードの変更

## サロン管理画面

- URL の末尾に `#admin` を付ける（またはお問合せ画面下部の「サロン管理者の方はこちら」）。
- パスコードはDB側（`app_settings.pin_hash`）で管理。初期値は `0000`。
  **管理者画面の「パスコードの変更」から、運用前に必ず変更してください。**
- 本番公開時は、より強固な認証（Supabase Auth 等）への切り替えも検討の余地あり（要件書7章）。
